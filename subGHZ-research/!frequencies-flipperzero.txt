This file catalogs frequencies discovered through Flipper Zero research.
For details on RX and TX capabilities, see https://docs.flipperzero.one/sub-ghz/frequencies

FCC Frequency Explorer can be very useful for identifying unknown frequencies, see https://fccid.io/frequency-explorer.php

Note for RFID Tags:
UHF RFID tag frequencies listed below typically are passive RFID tags and require an active reader
broadcasting a signal which is either backscattered or responded to on a different frequency by the
RFID tag. This means you'll only be able to pick up the UHF RFID tags below when they pass close
enough to an active reader. The tags are only activated when the broadcast from an active reader is
strong enough to energize the RFID tag. This effect was used by the Soviet Union in the late 1940s
to build a passive listening device which only transmitted audio when energized by an outside radio
signal source. You can read more at https://hackaday.com/2015/12/08/theremins-bug/

Vulnerability notation used in this file:
  [REPLAY]   - Fixed-code OOK signal; capture and retransmit to reproduce the original action
  [ROLLJAM]  - Rolling-code signal vulnerable to Samy Kamkar's RollJam attack (jam+capture+replay)
  [RELAY]    - Passive-entry system vulnerable to signal relay/amplification attack
  [DECODE]   - Plaintext/unencrypted protocol; decodable with rtl_433, URH, or Flipper Zero
  [JAM]      - Jamming this frequency denies service to dependent devices
  [SPOOF]    - Unauthenticated protocol allows injection of fabricated packets
  [TRACK]    - Device broadcasts a persistent unique ID enabling passive location tracking
  [PRIVACY]  - Transmission discloses sensitive personal or household data with no encryption
  [BRUTE]    - Fixed-code system with small keyspace; OpenSesame-class exhaustive attack feasible

**** 300-348 MHz ****
  Protocol notes for this band: Nearly all consumer devices use OOK (On-Off Keying) or ASK
  (Amplitude Shift Keying) modulation. Legacy garage and gate remotes in this band overwhelmingly
  use fixed codes with no rolling-code protection, making them trivially vulnerable to replay and
  OpenSesame-class brute-force attacks. Modern LiftMaster/Chamberlain Security+ 2.0 units on
  310/315/390 MHz do use rolling codes; older units on 303/304/309/312/318/320 MHz typically do not.

302.757  Gate / commercial entry remote (apartment complexes, storage facilities) [SD x3]
         Protocol: OOK fixed code
         [REPLAY] [BRUTE] Capture and retransmit to open gate. Small DIP-code keyspace (~4096).

303.000  Garage door opener - generic multi-code DIP switch remote (Linear, Stanley) [SD x2]
         Protocol: OOK fixed code (9-12 DIP switches)
         [REPLAY] [BRUTE] OpenSesame attack opens fixed-code door in <8 seconds.

303.875  LiftMaster / Chamberlain legacy garage door (pre-2011 fixed-code units) [SD x3]
         Protocol: OOK fixed code
         [REPLAY] [BRUTE] Most targeted legacy Chamberlain frequency. OpenSesame demonstrated live
         on this frequency. Residential garage frequently provides direct interior home access.

303.900  Multi-code legacy garage door openers (Linear, Stanley, Moore-O-Matic, older Chamberlain)

345.000  Honeywell ADEMCO / 2GIG wireless home security sensors [SD x1]
         (door/window contacts, PIR motion detectors - signature Honeywell frequency)
         Protocol: FSK / 2FSK, Honeywell ADEMCO proprietary - NO ENCRYPTION
         [DECODE] rtl_433 decodes ADEMCO packets in real-time: zone ID, sensor type, alert state,
                  battery level - all in plaintext. No authentication.
         [JAM] Jamming 345 MHz prevents sensor packets reaching the alarm panel. Door/window
               can be opened without triggering alarm. Documented in residential burglary cases.
         [REPLAY] Retransmit captured "all clear" packet to suppress zone alert at panel.
         [PRIVACY] Real-time occupancy: motion sensor activations reveal whether home is occupied,
                   sleep patterns, and room-by-room presence. Entry/exit events visible passively.
         VULN: No fix available in legacy ADEMCO hardware. Replace with Honeywell PROSIXCT or
               2GIG RE222 encrypted sensors + Honeywell Lyric / Resideo PRO-2000 panel.

868.350  LoRa / LoRaWAN IoT node or European-spec smart device [SD x1]

         [DECODE] gr-lora, LoRa hardware (TTGO LoRa32, LimeSDR) can capture/decode packets.

         [PRIVACY] IoT telemetry: may include asset location, environmental readings, metering data.

906.400  Itron / Landis+Gyr ERT smart meter (gas, electric, or water) [SD x2]
         Primary frequency for US Automatic Meter Reading (AMR) / AMI network. Meters broadcast
         every ~30 seconds. No encryption. No authentication.
         Protocol: Manchester-encoded OOK, ERT protocol
         [DECODE] rtlamr (open source, RTL-SDR) decodes Itron ERT packets in real-time. Output
                  includes: Meter ID, commodity type, consumption reading, tamper status.
         [PRIVACY] CRITICAL: Energy/gas/water consumption broadcast 24/7 in plaintext to any
                   receiver in range. Consumption data enables: occupancy detection (is anyone
                   home?), sleep/wake schedule inference, appliance usage patterns, vacancy
                   detection for burglary targeting. Documented since 2012; no OTA fix possible
                   on legacy ERT meters. Some utilities offer AMI upgrade programs on request.
         Note: No replay or injection applicable - ERT is broadcast-only.

915.000  US ISM band center - multiple device classes [SD x3]
         Device candidates: E-ZPass / SunPass / FasTrak RFID toll transponders, LoRa US915 nodes,
         Zigbee 915 MHz devices, smart building sensors, RFID inventory tags, industrial IoT
         Protocol: FHSS, LoRa, Zigbee, or proprietary narrowband
         [TRACK] E-ZPass transponders broadcast unique vehicle ID whenever interrogated by any
                 915 MHz reader - not only at toll plazas. Passive readers deployed at arbitrary
                 locations can track individual vehicles without consent. Linked to registration
                 data via state DOT. Documented by security researchers since 2013; unauthorized
                 readers observed deployed on city streets (NYC, 2013).
         [DECODE] LoRa US915: same attack surface as 868 MHz LoRaWAN (see above).
         [REPLAY] LoRa US915 join request replay (LoRaWAN 1.0.x, predictable DevNonce).
         [DECODE] Zigbee: network sniffing if AES-128 link key not properly managed.
         [DECODE] RFID inventory tags: passive tag ID capture with compatible reader hardware.
